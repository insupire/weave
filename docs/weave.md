# weave 설명서

분석 템플릿을 쓰는 쪽과 값을 채우는 쪽이 읽는다. **별도 카탈로그는 없고 이 문서가 카탈로그다.**
형상의 정본은 [`../schema/`](../schema) 의 JSON Schema 이고 이 문서는 그것을 사람이 읽는 형태다.

## 한 눈에

분석 템플릿 하나에 subject 마다 값 한 벌이 주입되어 분석뷰가 된다. 순위·등급 문법을 스키마에서 뺀 대신
**비교를 시각이 맡는다** — 나란히 늘어놓아 사람이 머릿속에서 견주게 하지 않는다.
다만 방법이 하나가 아니다. **겹칠 자리가 있는 것은 겹치고**(`line`, `rows` 가운데 `compare: "overlay"`),
**없는 것은 `focus` 가 무엇을 그릴지 고른다**(`stat`·`facts`·`bars`·`parts`, `rows` 가운데 `compare: "focus"`).

템플릿은 facet 의 배열이고, facet 하나는 **primitive element 하나와 그것이 요구하는 필드들**이다.
필드 선언의 `description` 이 그 필드가 무엇을 담는 자리인지 말한다. 무엇을 그릴지와 무엇이 들어갈지를 한 문서가 함께 말한다.

## 타입

값은 **기본 단위로 정규화**해서 담는다. 표시 단위는 렌더가 정한다.

| type | 담는 것 | 기본 단위 | JSON |
| --- | --- | --- | --- |
| `number` | 숫자 | 없음 | 수 |
| `money` | 금액 | 원 | 정수 (5,000만원 → `50000000`) |
| `ratio` | 비율 | 분수 | 수 (50% → `0.5`) |
| `multiple` | 배수 | 배 | 수 (두 배 → `2`) |
| `duration` | 기간 | 개월 | 정수 (20년 → `240`) |
| `age` | 나이 | 세 | 정수 |
| `boolean` | 참거짓 | — | `true` / `false` |
| `text` | 글 | — | 문자열 (긴 설명은 값이 아니라 주석에) |
| `date` | 날짜 | — | `"YYYY-MM-DD"` |

## 모양

| shape | 값의 생김새 | 함께 선언할 것 | 쓸 수 있는 type |
| --- | --- | --- | --- |
| `single` | 홑값 | `type` | 전부 |
| `range` | `{"min": …, "max": …}` — 한쪽만 알아도 된다 | `type` | 순서 있는 것 (`boolean`·`text` 제외) |
| `series` | `[{"at": 축값, "value": 값}, …]` — `at` 오름차순 | `type`, `axis` | `type` 은 수치형, `axis` 는 `age`·`date`·`duration`·`number` |
| `items` | `[{열key: 값}, …]` — 없는 열은 빈 칸 | `columns` | 열마다 `type` |

## primitive element

**렌더가 구현하는 것은 이것들이다. facet 종류는 없다** — facet 은 이 가운데 하나에 필드를 채운 것이다.

| element | 비교 | 그리는 것 | 아무도 없을 때 | 필드 수 | shape | type | 비고 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `stat` | focus 를 따라 바뀐다 | 값 하나를 크게. 고른 subject 의 것을 그린다 | 수 하나가 크게 설 자리를 그 크기 그대로 비운다. 필드 이름은 선다. 수가 설 칸과 단위가 서고, 그 위로 빛줄기를 지나가게 하는 것은 뷰어다 — 산출물은 자리만 낸다 | 1 | `single`·`range` | 9 가지 전부 | 겹칠 자리가 없어 focus 가 무엇을 그릴지 고른다. 고른 것이 없으면 첫 subject 다 |
| `facts` | focus 를 따라 바뀐다 | 라벨과 값 여럿. 고른 subject 의 것을 그린다 | 선언한 줄이 전부 선다. 이름 옆마다 값이 올 자리를 비운다. 줄마다 값의 생김새(수 칸이냐 글줄이냐)를 따르고, 그 위로 빛줄기를 지나가게 하는 것은 뷰어다 — 산출물은 자리만 낸다 | 1–12 | `single`·`range` | 9 가지 전부 | 한 facet 에 금액·나이·참거짓·글이 섞여도 읽는 규칙은 하나다. 표는 따로 없다 — 계약사항표 한 장도 이것 하나로 짠다 |
| `bars` | focus 를 따라 바뀐다 | 크기 비교. 고른 subject 의 막대를 그린다 | 필드마다 빈 자가 선다. 길이 0 의 막대가 아니라 채우지 않은 자다. 자마다 빛줄기가 지나갈 표식이 서고, 그것을 움직이는 것은 뷰어다 — 산출물은 자리만 낸다 | 1–6 | `single` | `number`·`money`·`ratio`·`multiple`·`duration`·`age` | 라벨·가로 막대·값이 한 줄로 눕고 붙은 말은 맨 앞 라벨 옆에 선다. 자는 facet 하나에 하나다 — 모든 필드·subject·고를 것을 덮으므로 무엇을 눌러도 자가 안 움직이고 한 facet 안의 막대끼리 길이를 견줄 수 있다. 범위가 크게 다른 필드를 한 facet 에 섞으면 작은 것이 짧아지는데, 그것이 축이 둘이라는 신호다 |
| `line` | 겹친다 | 축 위의 변화. subject 마다 선 하나가 한 좌표에 겹친다 | 두 축과 그림이 들어올 면만 선다. 값이 없으면 눈금도 없고 꺾은선도 없다 — 눈금을 지어내면 그것이 가짜 값이고, 고정된 꺾은선 하나는 눈금이 없어도 추세로 읽힌다. 그 면 위로 빛줄기를 지나가게 하는 것은 뷰어다 — 산출물은 자리만 낸다 | 1 | `series` | `number`·`money`·`ratio`·`multiple`·`duration`·`age` | 축이 둘이라 선끼리 갈린다. 누가 누구인지는 선 끝의 이름이 말해 아래에 범례를 두지 않고, 무엇을 보는 중인지는 지금·직전·나머지 세 갈래의 색과 굵기가 말한다. 고른 subject 가 선을 못 세웠을 때만 축 아래가 그 사실을 적는다. 가로축은 age·date·duration·number 만 된다 |
| `rows` | facet 의 compare 로 고른다(focus·overlay) | 항목을 표로 편다. compare 가 고른 것만 펼지 겹칠지를 가른다 — focus 는 고른 subject 의 항목만 행으로 펴고, overlay 는 항목 이름으로 겹쳐 subject 마다 열을 세운다 | focus 는 열 머리가 전부 선다 — 열은 템플릿이 선언한 것이라 subject 없이도 안다. overlay 는 키 열이 서고 그 옆 한 칸이 subject 가 올 자리로 비어 있는다 — 열은 subject 가 만든다. 어느 쪽이든 칸은 값의 생김새를 따르고, 그 위로 빛줄기를 지나가게 하는 것은 뷰어다 — 산출물은 자리만 낸다 | 1 | `items` | 9 가지 전부 | 같은 값(항목 배열)을 받는 같은 모양이라 겹치는 표와 하나만 펴는 표를 element 로 가르지 않고 facet 의 compare 가 스스로 말한다. overlay 는 누가 그 항목을 갖고 누가 안 갖는지를 한 줄에서 읽는다 — 목록을 못 읽어 모르는 것은 표기(—)로, 읽었고 그 항목이 없다는 아는 사실은 글(없음)로 선다 |
| `parts` | focus 를 따라 바뀐다 | 하나를 쪼갠 조각들. 합치면 한 덩어리가 된다 | 빈 띠가 선다. 조각 이름은 값이 갖고 오는 것이라 지어내지 않는다. 띠 위에 빛줄기가 지나갈 표식이 서고, 그것을 움직이는 것은 뷰어다 — 산출물은 자리만 낸다 | 1 | `items` | 9 가지 전부 | bars 와 다르다 — 막대는 서로 다른 것들의 크기를 견주고 여기 조각들은 한 덩어리의 안쪽이다. 한 subject 의 안을 나눈 것이라 겹칠 수 없어 focus 를 따른다. 파이가 아니라 띠로 그린다: 색으로 가르지 않으므로 조각마다 이름을 옆에 세울 수 있는 쪽이 읽힌다. 둘째 열이 몫이라 수치형이어야 한다 |

이 표는 **산출물**이다. 제약은 [`../schema/weave-template.schema.json`](../schema/weave-template.schema.json) 의
조건절에서, 산문과 보기는 [`../catalog/elements.json`](../catalog/elements.json) 에서 온다. `make viewer` 가 다시 쓴다.
뷰어의 설명서 페이지도 같은 카탈로그에서 나오므로 둘이 갈릴 수 없다.

제목과 설명 글은 primitive element 가 아니다. 제목은 facet 의 `title` 이고 설명은 주석이다.

## 템플릿

```json
{
  "weave": "1",
  "id": "tpl-0001",
  "title": "내 분석뷰",
  "facets": [
    {
      "id": "monthly-premium",
      "title": "월 보험료",
      "element": "stat",
      "fields": [
        {
          "key": "premium",
          "label": "월 보험료",
          "shape": "single",
          "type": "money",
          "description": "이 설계안의 월 납입 보험료 총액을 원 단위 정수로. 적립보험료가 섞여 있으면 분리하고 보장 보험료만."
        }
      ],
      "notes": [
        { "kind": "note", "text": "적립보험료를 뺀 보장 보험료입니다." },
        { "kind": "tip", "text": "같은 보장이라도 납입기간이 길면 월 보험료는 내려갑니다." }
      ]
    }
  ]
}
```

`facets` 의 순서가 그리는 순서다. **배치일 뿐 우열이 아니다.**

facet 의 `notes` 는 **템플릿 저작자가 다는 주석**이다. subject 와 무관한 지식 — 갱신과 비갱신의 차이 같은 것 — 은
값 한 벌이 아니라 여기 둔다. 값에 두면 subject 마다 같은 문장이 복제되고, **아직 채워진 subject 가 하나도 없을 때
그 지식이 통째로 사라진다.**

**facet 에 `description` 필드는 없다.** facet 을 설명하는 글도 `notes` 에 `note`(보충)로 적는다. 설명은 주석이라는 규칙이 하나다.

## 값 한 벌

subject 하나에 한 벌. 템플릿의 facet 과 필드를 **빠짐도 덤도 없이** 덮는다.

```json
{
  "weave": "1",
  "templateId": "tpl-0001",
  "subjectId": "proposal-a",
  "subjectLabel": "가 제안서",
  "facets": {
    "monthly-premium": {
      "fields": {
        "premium": {
          "state": "filled",
          "value": 87400,
          "notes": [{ "kind": "quote", "text": "합계보험료 87,400원" }]
        }
      },
      "notes": [{ "kind": "note", "text": "설계안 2쪽에서 읽었습니다." }]
    }
  }
}
```

상태는 **`filled` 와 `empty` 둘뿐**이다. `filled` 면 `value` 가 있고 `empty` 면 없다.
**왜 비었는지는 분류하지 않는다.** 「제안서에 없다」와 「약관이 아직 없다」는 둘 다 `empty` 이고, 까닭은 주석에 글로 적는다.

**subject 마다 값 한 벌이 정확히 하나 있다. 비어 있을 수 있다.**
「아직 채워지지 않았다」도 따로 된 상태가 아니다 — **전부 비어 있는 값 한 벌을 내고 주석으로 적는다.**
왜 없는지를 언어가 분류하지 않는다는 규칙이 여기에도 그대로 걸린다.

그 대가는 분명하다. 채우는 쪽이 빈 값 한 벌에 주석을 달지 않으면 화면은 그냥 「값 없음」이라고만 말한다.
아직 보지 못했다는 것을 말하려면 **적어야** 한다.

## 주석

| kind | 이름 | 무엇 |
| --- | --- | --- |
| `quote` | 인용 | 이 값이 어디서 왔는지. 원문 그대로 |
| `tip` | 팁 | 알아두면 좋은 것. 깨알 지식의 자리 |
| `note` | 보충 | 더 붙이는 말 |
| `caution` | 주의 | 한계와 조심할 것. 불확실하면 여기에 글로 적는다 |

**이 이름들이 정본이다.** 참조 뷰어가 이 이름으로 그린다. 같은 것을 두 이름으로 부르지 않는다.
제품 화면에 무엇이라 적을지는 앱이 정하고 여기에 묶이지 않는다.

**갈래는 세 자리에서 같다.** 자리가 누가 쓴 주석인지를 말한다.

| 어디 | 누가 | 무엇에 대해 |
| --- | --- | --- |
| 템플릿 facet 의 `notes` | 템플릿 저작자 | subject 와 무관한 것. 이 facet 이 무엇인지, 이 축을 볼 때 알아둘 것 |
| 값 한 벌 facet 의 `notes` | 채우는 쪽 | 이 subject 의 이 facet 전체에 대한 것 |
| 값 한 벌 필드의 `notes` | 채우는 쪽 | 이 subject 의 이 값 하나에 대한 것 |

확실성 수치는 어느 자리에도 없다. 불확실하면 `caution` 에 글로 적는다.

## 고르는 자리 — 사람이 고르면 값이 바뀐다

선택 하나가 여러 facet 의 값을 한꺼번에 바꿔야 할 때가 있다. 그것이 **고르는 자리**다.
**없는 것이 기본이다.** 쓰는 템플릿만 선언한다.

```json
// 템플릿 — 무엇을 고를 수 있는가
"choices": [ { "id": "illness", "label": "무엇에 걸렸을 때", "options": [
  { "id": "cancer", "label": "암" }, { "id": "brain", "label": "뇌혈관" }
] } ],
"facets": [ { "id": "payout", "element": "stat", "fields": [
  { "key": "diagnosis-benefit", "label": "진단금", "shape": "single", "type": "money",
    "choice": "illness", "description": "고른 것의 진단금을 원 단위 정수로." }
] } ]
```
```json
// 값 한 벌 — 타는 필드는 고를 것마다 하나
"fields": { "diagnosis-benefit": { "byOption": {
  "cancer": { "state": "filled", "value": 30000000 },
  "brain":  { "state": "empty" }
} } }
```
```json
// 렌더 인자 — 무엇을 골랐는가
"choices": { "illness": "cancer" }
```

- **고른 것은 인자, 고를 수 있는 것은 골격이다.** 목록은 **템플릿**이 갖는다 —
  facet 을 템플릿이 갖는 것과 같은 까닭이다. subject 마다 고를 것이 다르면 견줄 수가 없다.
- **선택자는 facet 안에 선다.** 축은 그 facet 이 **무엇에 대한 값인지**를 말하므로 내용이다.
  화면 전체에 걸리는 것(`focus`·명단·상태 줄)만 껍데기라 밖에 남는다 — 선이 거기다.
  렌더는 타는 facet 마다 `<div class="choice" data-choice="…">` 자리를 내고 그 안에
  고를 것을 `data-option` 으로 놓는다. **첫 facet 에만 두지 않는다** — 나머지가 까닭 없이
  바뀌고 facet 차례가 뜻을 지게 된다.
- **축은 이름으로 선언되고 여러 facet 이 같은 축을 탄다.** 한 번 고르면 전부 따라온다.
  어느 축을 타는지는 **facet 이 제 필드로 말한다** — 따로 적지 않는다(두 군데 적으면 어긋난다).
- **모양은 언어가 말하지 않는다.** 칩·드롭다운·세그먼트 중 무엇으로 그릴지는 앱이 정한다.
  우리가 내는 것은 **무엇을 고를 수 있고 지금 무엇이 골라져 있는가**뿐이다.
- **고른 것이 바뀌어도 어떤 facet 이 서는지는 달라지지 않는다.** 달라지는 것은 `choice` 를 단 필드의 값뿐이다.
  「이것을 골랐을 때만 나타나는 facet」은 조건부 facet 이고, 그건 [일부러 없는 것](#일부러-없는-것)이다.
- **한 facet 안에서 타는 필드와 안 타는 필드가 섞일 수 있다.** 월 보험료는 설계 하나에 하나뿐이라 타지 않는다.
- **한 필드는 한 자리만 탄다.** 둘을 타면 값이 곱해진다. 한 facet 이 여러 축을 타는 것은
  된다 — 필드마다 다른 축을 타면 값은 **더한 만큼**만 늘고 곱해지지 않는다.
- 고를 것은 **둘부터**다. 하나뿐이면 고르는 것이 아니다.
- **자리 자체에 뜻이 없다.** 「질병」이라는 말은 스키마에 없고, 무엇을 고르는 것인지는 라벨이 말한다.

**대가.** 자리를 하나 선언하면 그것을 타는 **모든 필드가 고를 것마다 값을 채워야 한다.**
고를 것이 여섯이면 값도 여섯이다. 자리를 둘 선언하고 서로 다른 필드가 타게 하면 값은 더한 만큼 늘고,
같은 뜻을 두 자리로 쪼개면 채울 것이 곱해진다. 검사기가 **빠짐도 덤도 없이** 덮는지 보므로
선언한 만큼의 값이 없으면 바로 걸린다 — 값이 비싸다는 것이 쓰는 쪽에 드러난다.

## 렌더 인자

**값 한 벌이 이미 아는 것은 인자가 아니다.** 여기 서는 것은 **앱만 아는 상호작용 이력** 둘뿐이다.
둘 다 **index 가 아니라 subject 의 id** 로 가리키고, `null` 이 없음이며, 없는 id 면 그 상태만 사라진다.

| 인자 | 무엇 |
| --- | --- |
| `focus` | 지금 보고 있는 subject. `null` 이 release 다 |
| `previousFocus` | **바로 전에** 보고 있던 subject. `focus` 와 같은 id 면 **직전이 없는 것으로 본다** — 직전이 현재와 같을 수는 없다 |
| `choices` | [고르는 자리](#고르는-자리--사람이-고르면-값이-바뀐다)마다 무엇을 골랐는지의 지도. 빠졌거나 없는 id 면 **첫 option** 을 그린다 |

`previousFocus` 와 `choices` 는 값에서 유도할 수 없다. 사용자가 무엇을 눌러 왔는지만이 안다.
**고를 수 있는 것은 여기 서지 않는다** — 명단은 값 한 벌들이, 고를 것의 목록은 템플릿이 이미 말한다.

**누가 자리에 서는지는 인자가 아니다.** subject 마다 값 한 벌이 정확히 하나 있으므로 **값 한 벌들이 곧 명단**이고,
차례는 넘어온 차례이며 이름은 각 값 한 벌의 `subjectLabel` 이 이미 갖고 있다. 차례는 배치일 뿐 우열이 아니다.

## 렌더가 하기로 돼 있는 것

참조 뷰어가 기준이다. 앱은 자기 시각을 입히되 아래는 지킨다.

- **비교하는 법이 primitive element 마다 다르다.** 겹칠 자리가 있는 것만 겹친다.
  - `line` 은 **겹친다** — 축이라는 공유하는 자리가 있어 겹칠수록 읽을 것이 많아진다.
  - `rows` 는 같은 값(항목 배열)을 받는 facet 이 `compare` 로 스스로 고른다 — `overlay` 는
    항목 이름으로 겹쳐 subject 마다 열을 세우고, `focus` 는 지금 보는 subject 것만 편다.
    겹치는 표와 하나만 펴는 표는 다른 표현 단위지만 같은 모양이라, element 를 둘로 가르는
    대신 facet 이 스스로 말하게 줄였다. 한 facet 은 여전히 `compare` 하나만 가지므로
    비교 축은 하나다.
  - `parts` 는 **하나를 쪼갠 것**이라 겹칠 수 없다. 두 subject 의 안이 한 덩어리가 될 수 없다.
- **그림은 값과 같은 자로 재어진다.** 길이가 값을 뜻한다면 그 자는 **무엇을 눌러도 안 움직여야** 한다.
  `bars` 의 자는 **facet 하나에 하나**이고 그 facet 의 **모든 필드 × 모든 subject × 모든 고를 것**을 덮는다.
  `line` 의 두 축도 같다. 「한 facet 은 비교 축 하나여야 한다」가 여기서 **시각으로 강제된다** —
  범위가 크게 다른 필드를 한 facet 에 섞으면 작은 것이 짧아지고, 그것이 축이 둘이라는 신호다.
- **0 이 아닌 값은 길이 0 이 되지 않는다.** 사라지면 「값이 없다」와 구별이 안 된다.
  아주 작은 몫은 바닥(전체의 0.8%)까지 늘려 그리고, **정확한 수는 늘 옆에 적힌다.** 0 은 진짜 0 이라 길이가 0 이다.
  - `stat` · `facts` · `bars` 는 **`focus` 를 따라 바뀐다** — 겹칠 자리가 없어 억지로 늘어놓는 대신
    무엇을 그릴지 `focus` 가 고른다.
- **제목은 이름이고 「이것이 무엇인지」는 `hint` 가 진다.** 제목이 설명까지 지면 화면을
  훑을 때 무엇에 대한 자리인지가 한눈에 안 들어온다. 제목은 **명사구로 짧게** 쓴다 —
  「보험료 구성」이지 「내 보험료가 어디에 쓰이나」가 아니다.

  | | 이름 | 이것이 무엇인지 | 그것에 대한 말 |
  | --- | --- | --- | --- |
  | facet | `title` | **`hint` — 제목 아래 늘 보인다**(1~120자 한 줄) | 주석 |
  | field | `label` | `hint` — **이름 옆 표시를 열면**(1~80자 한 줄) | 주석 |

  **뜻은 층마다 같고 보이는 방식만 다르다. 근거는 밀도다** — facet 은 화면에 서넛이라
  한 줄씩 붙어도 길어지지 않고, 필드는 열 개씩이라 늘 보이면 값보다 설명이 길어진다.
- **필드에 붙는 글이 셋이고 받는 사람이 다르다.** 셋을 가르면 쓸 때 고민이 없다.

  | | 누구에게 | 무엇을 | 어디에 | 길이 |
  | --- | --- | --- | --- | --- |
  | `description` | **채우는 쪽에게** | 무엇을 어떤 단위로 담는 자리인지 | 화면에 **안 나온다** | 10~600자 |
  | `hint` | **읽는 사람에게** | **이 필드가 무엇인지** | **이름 옆** 표시를 열면 | 1~80자, 한 줄 |
  | 값 한 벌 필드의 `notes` | 읽는 사람에게 | **이 값에 대해 할 말** | **값 옆** 표시를 열면 | 주석 규칙 |

  **자리가 뜻을 가른다** — 이름 옆은 템플릿의 것(모든 subject 에 같다), 값 옆은 그 subject 의 것.
  양끝으로 갈리니 섞이지 않는다. 여는·닫는 길은 둘이 **같은 것**을 쓴다(가리키기·초점·누르기,
  `Esc`·닫기·바깥 누르기). 이름이 적히는 자리는 element 마다 다르다 — `facts` 는 행 라벨,
  `bars` 는 막대 라벨, 나머지는 필드 라벨이다. `line` 과 `rows` 는 값이 설 한 자리가 없어
  두 표시가 이름 줄에 나란히 서고, **앞이 `hint`, 뒤가 값 주석**이다.

  `hint` 는 **값이 없어도 필요하다** — 「납입기간」이 무엇인지는 그 제안서에 값이 있든 없든 같다.
  주석은 그 값이 있고 나서 할 말이다. 쓰는 때가 달라서 가른다.
  `hint` 는 **필드에 매인다** — 값과 무관한 자유 문장은 「혼자 서는 글」이고 facet 주석의 자리다.
- **facet 에 붙는 주석은 둘이다.** 템플릿의 것은 저작자가 쓴 subject 무관 지식, 값 한 벌의 것은
  채우는 쪽이 그 subject 에 대해 쓴 말. 둘 다 본문 아래에 펼쳐지고, 고른 subject 의 것만 선다.
- **`focus` 가 없으면 첫 subject 를 그린다.** 늘어놓기로 돌아가지 않고, 빈 화면을 내지 않는다.
  없는 id 일 때도 같다 — 사라지면 무엇을 그릴지가 정해져 있다.
- **무엇을 보고 있는지 늘 읽힌다.** 겹치지 않는 facet 은 그리고 있는 subject 의 이름을 함께 낸다.
- **순위가 되면 안 된다.** 누가 큰지 눈에 보이는 것이 정본이 원하는 것이지만 거기서 한 걸음 더
  나가지 않는다 — 1등 표시, 순위로 읽히는 정렬, 좋고 나쁨을 말하는 색과 부호를 두지 않는다.
- **값이 없는 것이 사라지면 안 된다.** 겹치는 쪽은 축 아래에 「누가 없다」를 적고, 바뀌는 쪽은 그 subject 의
  빈 필드에 **표기**를 세운다. 빈 칸으로 두지 않는다 — 렌더가 깨진 것과 구별되지 않는다.

**렌더가 내는 것은 분석뷰뿐이다** — 템플릿 제목과 facet 들. 도구의 표시(템플릿 id·subject 수·focus 상태·
범례·명단·primitive element 이름)는 렌더에 들어가지 않는다. 앱이 이 출력을 그대로 가져다 쓸 때 따라가면 안 되기 때문이다.
그런 것이 필요하면 화면 상태로 따로 받아 앱이 자기 자리에 그린다.

- **subject 하나에 값이 없으면 facet 이 그 사실을 말한다.** 그 자리를 숨기지 않는다 —
  숨기면 subject 마다 골격이 달라져 견줄 수 없다.
- **다만 모든 subject 에 값이 없는 facet 은 서지 않는다.** 아무에게도 없으면 골격이 달라질 일이 없고 빈 카드만 남는다.
  고르는 자리가 있으면 「이것을 골랐을 때는 아무도 값이 없다」도 같은 자리다.
  **말이 붙어 있으면 선다** — 「아직 값을 채우지 않았습니다」가 적힌 카드는 빈 카드가 아니고,
  전부 비어 있는 값 한 벌이 그 사실을 말하는 길이 그것이다. subject 가 하나도 없으면 이 규칙을 쓰지 않는다.
- **전부 비어 있는 값 한 벌도 자리를 얻고 골격을 그대로 그린다.** 모든 facet 이 없다고 말하고, 왜인지는 주석이 말한다.
- **표기는 「모른다」를 가리킨다. 아는 사실은 글로 말한다.** 표기의 뜻은 이름표(`aria-label`·`title`)가 글로 갖고,
  빈 칸으로 두지 않는다 — 렌더가 깨진 것과 구별되지 않는다.

  | 무슨 뜻 | 어떻게 | 어디 |
  | --- | --- | --- |
  | 그 필드에 값이 없다 — **모른다** | `—` (이름표 「값 없음」) | 값이 설 자리 |
  | 목록은 읽었고 그 항목이 여기 없다 — **안다** | 「없음」 | `rows`(overlay) 의 칸 |
  | 목록 자체가 비었다 — **안다** | 「항목 없음」 | 표가 설 자리 |
  | 항목은 있는데 보여 줄 열이 없다 — **안다** | 「있음」 | `rows`(overlay) 의 칸 |
  | **템플릿과 값이 어긋나 그릴 수 없다** | 「그리지 못한다: …」 | 그 자리. **표기로 줄지 않는다** — 값의 문제가 아니라서 조용해지면 안 된다 |

- **겹치는 쪽에서 값이 없다는 말은 고른 subject 것만 선다.** `line` 은 **고른 subject 가 선을 못 세웠을 때만**
  축 아래에 그 사실을 적는다. 못 그린 것을 줄줄이 적으면 그것이 범례다 — 누가 누구인지는 선 끝의 이름이 말한다.
- **주석은 붙은 자리에 그대로 보인다.** 템플릿 facet 의 것, 값 한 벌 facet 의 것, 값의 것.
  facet 에 붙은 것은 본문에 펼치고, **필드에 붙은 것은 표시를 세워 가리키면 연다.**
  값 옆의 표시는 **하나이고 중립**이다 — 「여기 붙은 말이 있다」만 말한다. 수도 적지 않는다.
  `bars` 에서는 값이 아니라 **맨 앞 라벨 옆**, `line` 과 `rows`(overlay) 에서는 **필드 라벨 옆**에 선다.
  **어느 element 에서나 값에 붙은 말은 표시를 가리켜야 열린다** — 본문 아래에 펼치지 않는다.
  **갈래는 열었을 때 산다** — 툴팁 안에서 줄마다 자기 갈래 표시와 색을 갖는다.
- **말은 데이터 뒤에 한자리에 모인다.** facet 제목 → 본문 → facet 주석 → subject 주석.
  예외를 두지 않는다 — 읽는 규칙이 둘이면 매번 어디 있는지 찾게 된다.
  **줄 사이는 전부 같은 자다.** 두 묶음을 가르는 것은 여백이 아니라 그 사이의 **짧은 선**이다 — 한쪽이 비면 서지 않는다.
  주석 앞에 subject 이름을 붙이지 않는다. 늘 고른 subject 것만 나오므로 이름이 그 사실을 두 번 말한다.
- **subject 를 색으로 가르지 않는다.** 가르는 것은 **이름**이다 — 겹친 `line` 의 선 끝에도 이름이 선다.
- **`line` 의 선은 보는 상태로 갈린다** — 지금 보는 것 · 직전에 보던 것 · 나머지 셋.
  **subject 의 색이 아니라 상태의 색**이라 같은 subject 라도 `focus` 가 옮겨 가면 바뀐다.
  색에만 기대지 않는다 — 굵기와 진하기가 같은 순서를 함께 말해 **색 없이도 갈린다.**
  뚜렷한 것이 「더 좋은 것」이 아니라 **보고 있는 것**이다.
- **subject 의 주석은 언제나 고른 subject 것이다.** primitive element 로 갈리지 않는다 —
  겹쳐 그리는 facet 이라도 아래에 서는 말은 지금 고른 subject 것이고, `focus` 를 옮기면 말이 따라온다.
  `focus` 가 없으면 첫 subject 다. **facet 에 붙은 주석은 그대로 전부 선다** — 그건 subject 의 것이 아니다.
- **subject 가 하나도 없어도 원소마다 제 자리가 선다.** 골격만 세우고 원소 안을 비우지 않는다 —
  아래 「아무도 없을 때」를 본다.
- **없는 focus id 면 분석뷰가 focus 를 놓은 것과 똑같아진다.** 렌더에 안내 문구가 끼지 않는다.
- **순위·등급을 렌더가 되살리지 않는다.** 스키마에서 뺀 것을 색이나 배치로 다시 만들지 않는다.

subject 명단은 인자가 아니라 **값 한 벌들 자체**다.

## 만져 보기

저장소 뿌리의 [`viewer.html`](../viewer.html) 을 **브라우저로 연다.** 서버도 설치도 없다.
이 한 장이 weave 의 설명서다 — 왼쪽 목차에 primitive element 가 하나씩 서고, 각 쪽은 제약과
최소 템플릿 조각과 **그 자리에서 그린 모습**을 함께 보인다. 목차의 마지막이 플레이그라운드이고,
거기서 [`samples/`](../samples) 의 샘플을 골라 직접 고쳐 가며 화면이 어떻게 되는지 본다.

**설명서는 판정하지 않는다.** JSON 으로 읽히는지만 본다. 맞는지는 검사기가 말한다.

```sh
python -m weave template samples/all-elements/template.json
python -m weave values --template samples/all-elements/template.json samples/all-elements/values-*.json
python -m weave args args.json
```

## 그리지 않는 화면

**weave 는 「값이 있을 때의 분석뷰」 언어다.** 못 그리는 것이 아니라 **안 그리는 것**이다.

값을 채우지 못했다 · 재료가 아직 준비되지 않았다 · 사용자가 건너뛰었다 · 결과를 아직 못 받았다 —
이런 상태 화면은 **앱의 것**이다. 언어가 그것까지 맡으면 「왜 없는지를 분류하지 않는다」는 규칙이
그 자리에서 깨지고, 상태 갈래가 늘 때마다 스키마를 고쳐야 한다.

경계는 이렇다. **값 한 벌이 있으면 분석뷰다** — 전부 비어 있어도 그렇고, 그때는 빈 값과 주석이
「아직 채우지 않았다」를 말한다. **값 한 벌을 만들 단계에 이르지 못했으면 앱의 상태 화면이다.**

## 아무도 없을 때 — subject 0

**값 한 벌이 하나도 없는 것은 없는 화면이 아니라 첫 화면이다.** 사람이 자기 분석뷰를 먼저 짜고
제안서가 오기를 기다리는 자리가 여기다. 그러니 이 화면이 말할 것은 「값이 없다」가 아니라
**「여기에 무엇이 올지」**다.

- **골격이 그대로 선다.** facet 제목 · `hint` · 템플릿 주석은 값과 무관하게 템플릿의 것이다.
  「전원 결손 facet 은 빠진다」는 규칙은 **여기에 적용하지 않는다** — 뺄 값 한 벌 자체가 없다.
- **원소마다 제 자리가 선다.** 무엇이 서는지는 카탈로그 표의 「아무도 없을 때」 칸이 정본이다.
  선언한 것(필드 이름 · 열 머리 · 축)은 서고, 값이 갖고 오는 것(subject 이름 · 조각 이름 · 눈금)은 안 선다.
- **표기를 쓰지 않는다.** `—` 는 「어떤 subject 의 값을 모른다」는 말인데 여기엔 모를 subject 가 없다.
  「없음」·「항목 없음」 같은 글도 아직 할 말이 아니다.
- **가짜 값을 그리지 않는다.** 예시 숫자도, 흐린 더미 값도 없다. 그려도 되는 것은 **자리**뿐이다.
- **자리의 모양이 값의 생김새를 따른다.** 밑줄 하나가 아니라 **수가 설 칸과 단위**(금액이면 수 칸과 `원`),
  **글줄**, **자**, **축**이다. 칸 수는 **타입마다 고정**이라 자릿수가 크기를 말하지 않는다.
- **움직임은 뷰어의 것이다.** `renderView` 의 출력에는 시간도 프레임도 애니메이션 지시도 **한 글자 없다** —
  자리 표식(`.slot` 과 그 안의 칸, `.track` · `.band` · `.plot`, 그리고 `.sheen`)만 서고
  **스타일시트가 그 위로 빛줄기를 지나가게 한다.** 앱은 같은 표식 위에 제 방식을 얹으면 된다.
  「산출물에 디자인이 없다」가 그대로 선다.
  - **지키는 선은 하나다.** 정지한 회색 `0` 은 이 도메인에서 **진짜 값**으로 읽힌다 — 미보장이 0원이다.
    그래서 **빈 자리에는 눈금도 수도 이름도 글자도 그리지 않는다.** 읽을 것이 없으면 값도 없다.
    - 예전에는 **「한 모양이 고정되지 않는다」**가 함께 섰다. 그것은 움직이는 가짜 값이 읽히는 것을
      막으려던 **수단**이었고, 읽힐 것을 아예 안 그리는 지금은 필요가 없다 — 고정된 회색 덩어리는
      값으로 읽히지 않는다.
  - **밑그림은 원소마다 다르다.** `stat` 은 큰 덩어리 하나, `facts` 는 줄 여럿, `bars` 는 가로 막대 여럿,
    `line` 은 축과 그림 자리, `rows` 는 칸, `parts` 는 띠. **`line` 에 꺾은선을 그리지 않는다** —
    고정된 꺾은선 하나는 눈금이 없어도 **추세로 읽히고**, 「오르는 중」은 눈금이 없어도 값이다.
  - **움직임은 빛줄기 하나뿐이다.** 옅은 빛줄기가 그 밑그림 위를 쓸고 지나간다. **모든 원소가 같은 방향·
    같은 속도·같은 세기**이고 속도는 변수 하나(`--sheen`)에서만 나온다. 자리마다 위상을 어긋내지 않는다 —
    전부 같이 움직이는 것이 자리 표시가 한 벌로 읽히는 까닭이다. 효과를 여럿 두고 박자를 맞추는 것이
    아니라 **효과를 하나로 줄여서** 일관을 얻는다.
  - **`prefers-reduced-motion` 을 존중한다.** 멎는 것은 **빛줄기뿐**이고 밑그림은 그대로 선다 —
    자리가 통째로 사라지면 「여기에 무엇이 온다」가 없어진다.
- **고르는 자리는 선다.** 축은 값이 아니라 템플릿의 것이라, 아직 아무도 없어도 무엇으로 볼지는 고를 수 있다.
- **`focus` 는 가리킬 것이 없다.** 없는 id 를 줄 때와 같이 조용히 놓인다.

## 일부러 없는 것

순위 · 등급 · 점수 · 경고색 · 확실성 수치 · 조건부 facet · 결론 문장 문법 · 중간 트리 산출물 · 자유 설정 주머니.
객관성을 문서가 아니라 스키마로 강제하는 자리다. **문법에 없으므로 나올 수 없다.**

## 스키마가 못 지키는 것

- **한 facet 은 비교 축 하나여야 한다.** 의미의 문제라 템플릿을 쓰는 쪽이 지킨다.
- **`description` 에 「등급을 A~E 로 매겨라」라고 적는 것.** 자연어는 검사하지 않는다.
- **잘못 정규화한 값.** `ratio` 에 `50`(= 5000%) 을 넣어도 수치로는 옳다. 정수 여부와 날짜 형식만 본다.

## 요소 하나하나

앞 절들이 쓰는 법을 말했다면 여기는 **자리를 전부 센다.** 두 문서에 설 수 있는 것과 그것들이
함께 쓰는 공통 정의가 빠짐없이 있다.

**이 절은 산출물이다.** 어느 자리가 있는가도, 그 자리가 무엇인가도
[`../schema/`](../schema) 의 `description` 이 정본이고 여기는 그것을 한 줄씩 편 자리다 —
같은 말을 두 벌로 갖지 않는다. 스키마에 칸이 늘면 `make viewer` 가 이 표를 따라 키운다.

먼저 경계 셋을 읽으면 표가 쉽다.

- **템플릿은 subject 를 모른다.** 그래서 subject 와 무관한 지식은 템플릿의 주석에 살고,
  그 subject 에 대한 사실은 값 한 벌의 주석에 산다.
- **값은 라벨을 갖지 않는다.** 분석뷰 제목도 필드 이름도 열 이름도 전부 템플릿에서 온다.
- **`state` 는 값의 것이다.** 템플릿은 어느 자리가 설지를 선언하고, 그 자리가 찼는지는
  채운 쪽만 안다.

「필수」와 「선택」은 그 자리가 늘 있어야 하는가다. **모양과 element 에 따라 더 걸리는 조건**은
([모양](#모양)의 「함께 선언할 것」과 [primitive element](#primitive-element) 표) 거기서 읽는다.

### 분석 템플릿 — [`weave-template.schema.json`](../schema/weave-template.schema.json)

템플릿의 것. **저작 때** 정해진다. subject 가 누구든 같다.

**문서 뿌리** — 무엇을 그릴지와 각 필드가 무엇을 담는지를 함께 말한다. 값 한 벌이 여기 선언된 필드를 채운다.

| 자리 | 무엇인가 | 필수·선택 |
| --- | --- | --- |
| `weave` | 스키마 버전. 지금은 1 뿐이다. | 필수 |
| `id` | 바깥에서 온 식별자. 템플릿 id 와 subject id 가 쓴다. | 필수 |
| `title` | 이 분석뷰의 제목. 화면 맨 위에 선다. | 필수 |
| `choices` | 고르는 자리. 사람이 하나를 고르면 그것을 타는 필드의 값이 바뀐다. 무엇을 고를 수 있는지만 말하고 **어떻게 생겼는지는 말하지 않는다** — 칩인지 드롭다운인지는 앱이 정한다. 골격이므로 값 한 벌이 아니라 여기 선다: subject 마다 고를 것이 다르면 견줄 수가 없다. 고른 것이 바뀌어도 **어떤 facet 이 서는지는 달라지지 않는다** — 달라지는 것은 그것을 타는 필드의 값뿐이다. 여럿 선언할 수 있으나 선언한 만큼 값을 채워야 한다. | 선택 |
| `facets` | 그리는 순서대로. 순서는 배치일 뿐 우열이 아니다. | 필수 |

**`Choice`** — 고르는 자리 하나. 고를 것이 하나뿐이면 고르는 것이 아니므로 둘부터 선다.

| 자리 | 무엇인가 | 필수·선택 |
| --- | --- | --- |
| `id` | 템플릿이 짓는 이름. facet id · 필드 key · 열 key 가 쓴다. | 필수 |
| `label` | 이 고르는 자리의 이름. 화면에 보인다. | 필수 |
| `options` | 고를 수 있는 것들. 값 한 벌은 이 id 마다 값을 하나씩 채운다. | 필수 |

**`Option`** — 고를 것 하나. 값 한 벌은 이 id 마다 값을 하나 채운다.

| 자리 | 무엇인가 | 필수·선택 |
| --- | --- | --- |
| `id` | 템플릿이 짓는 이름. facet id · 필드 key · 열 key 가 쓴다. | 필수 |
| `label` | 고를 것의 이름. 화면에 보인다. | 필수 |

**`Facet`** — 분석뷰의 한 조각. primitive element 하나와 그것이 요구하는 필드들.

| 자리 | 무엇인가 | 필수·선택 |
| --- | --- | --- |
| `id` | 템플릿이 짓는 이름. facet id · 필드 key · 열 key 가 쓴다. | 필수 |
| `title` | 이 facet 의 이름. 짧은 명사구로 쓰고 설명은 hint 가 진다. | 필수 |
| `hint` | 이 facet 이 무엇인지 한 문장. 제목 아래에 **늘 보인다.** 제목은 짧은 이름이고 설명은 여기 산다 — 제목이 설명까지 지면 화면을 훑을 때 무엇에 대한 자리인지가 한눈에 안 들어온다. 필드의 hint 와 뜻이 같다: 층만 다르다. 필드 것보다 조금 긴 것은 facet 하나를 통째로 말하기 때문이고, 늘 보이는 것은 facet 이 화면에 서넛뿐이라 한 줄씩 붙어도 길어지지 않기 때문이다. | 선택 |
| `element` | primitive element. 렌더가 구현하는 것은 이 목록뿐이다. | 필수 |
| `compare` | `rows` 에서만 쓴다. 항목을 겹칠지(overlay) 고른 것만 펼지(focus)를 이 facet 이 스스로 말한다 — 두 표현 단위가 다른 element 였던 것을 하나로 줄이고 겹침을 이 자리로 옮겼다. 다른 element 는 비교하는 법이 이름 자체로 정해지므로 이 자리를 갖지 않는다. | 선택 |
| `fields` | 이 facet 이 그릴 값들의 선언. 몇 개까지 서는지와 어떤 shape·type 이 되는지는 element 가 정한다. | 필수 |
| `notes` | 템플릿 저작자가 다는 주석. facet 의 설명 글도 여기 산다 — description 필드는 따로 없다. subject 와 무관한 지식은 값이 아니라 여기 둔다. | 선택 |

**`Field`** — 값 하나가 설 자리의 선언. description 이 무엇을 담는 자리인지 말한다.

| 자리 | 무엇인가 | 필수·선택 |
| --- | --- | --- |
| `key` | 템플릿이 짓는 이름. facet id · 필드 key · 열 key 가 쓴다. | 필수 |
| `label` | 이 필드의 이름. 화면에서 값 옆에 선다 — 이름은 템플릿의 것이라 subject 가 바뀌어도 같다. | 필수 |
| `shape` | 한 필드가 담는 값의 모양. | 필수 |
| `type` | 값의 타입. 렌더는 이 닫힌 목록에만 의존한다. | 선택 |
| `axis` | series 의 가로축이 될 수 있는 타입. | 선택 |
| `choice` | 이 필드가 타는 고르는 자리의 id. 있으면 그 자리의 고를 것마다 값이 따로 있다. 템플릿이 선언하지 않은 id 는 쓸 수 없다. 한 필드는 한 자리만 탄다 — 둘을 타면 값이 곱해진다. | 선택 |
| `hint` | 읽는 사람에게 **늘 보이는 한 줄.** 이 필드가 무엇인지를 말한다 — 값이 없어도 필요한 말이다. 주석과 다르다: 주석은 **이 값에 대해 할 말**이고 hint 는 **이 필드가 무엇인가**다. description 과도 다르다: **독자**가 갈린다 — hint 는 보는 사람이 늘 읽고, description 은 이 필드를 채우는 쪽이 읽으며 화면에 나오지 않는다. 한 줄이고 필드에 매인다: 값과 무관한 자유 문장을 여기 두지 않는다. | 선택 |
| `allowed` | 값이 이 목록 안에 있어야 한다. 자유 글에서 오타와 변종을 막는 자리다. text 를 담는 single 필드에만 쓴다. | 선택 |
| `columns` | items 필드가 담을 항목의 열 선언. shape 가 items 일 때만 선다. | 선택 |
| `description` | 이 필드의 설명. 무엇을 담는 자리인지를 기본 단위까지 자연어로 적는다. 채우는 쪽이 읽고 화면에는 나오지 않는다. | 필수 |

**`Column`** — items 한 칸의 선언. 열도 제 description 을 갖는다.

| 자리 | 무엇인가 | 필수·선택 |
| --- | --- | --- |
| `key` | 템플릿이 짓는 이름. facet id · 필드 key · 열 key 가 쓴다. | 필수 |
| `label` | 이 열의 이름. 표의 머리에 선다. | 필수 |
| `type` | 값의 타입. 렌더는 이 닫힌 목록에만 의존한다. | 필수 |
| `description` | 이 열의 설명. 필드의 description 과 같은 자리다 — 채우는 쪽이 읽고 화면에는 나오지 않는다. | 필수 |

### 값 한 벌 — [`weave-valueset.schema.json`](../schema/weave-valueset.schema.json)

값 한 벌의 것. **채울 때** 정해진다. subject 마다 다르다.

**문서 뿌리** — subject 하나에 대한 필드별 상태와 값과 주석. subject 하나당 한 벌이다. 아직 채워지지 않은 subject 는 이 문서 자체가 없다.

| 자리 | 무엇인가 | 필수·선택 |
| --- | --- | --- |
| `weave` | 스키마 버전. 지금은 1 뿐이다. | 필수 |
| `templateId` | 바깥에서 온 식별자. 템플릿 id 와 subject id 가 쓴다. | 필수 |
| `subjectId` | 바깥에서 온 식별자. 템플릿 id 와 subject id 가 쓴다. | 필수 |
| `subjectLabel` | 화면에 쓸 이름. 없으면 렌더가 subjectId 를 쓴다. | 선택 |
| `facets` | 템플릿의 facet id 를 키로. 빠짐도 덤도 없이 전부 덮는다. | 필수 |

**`FacetValues`** — facet 하나에 대한 이 subject 의 값들. 라벨은 갖지 않는다 — 제목과 이름은 전부 템플릿에서 온다.

| 자리 | 무엇인가 | 필수·선택 |
| --- | --- | --- |
| `fields` | 템플릿이 이 facet 에 선언한 필드 key 를 키로. 빠짐도 덤도 없이 전부 덮는다. | 필수 |
| `notes` | 이 subject 의 이 facet 전체에 대해 할 말. subject 와 무관한 지식은 템플릿 쪽 notes 에 둔다. | 선택 |

**`FieldSlot`** — 필드 한 자리. 고르는 자리를 타지 않는 필드면 값 하나이고, 템플릿이 choice 를 단 필드면 byOption 으로 고를 것마다 하나다. **어느 쪽이어야 하는지는 템플릿이 정한다** — 여기서는 둘 다 받고, 대조는 검사기가 한다. 고른 값 안에 또 고를 것을 둘 수는 없다.

| 자리 | 무엇인가 | 필수·선택 |
| --- | --- | --- |
| `state` | 이 자리가 찼는지. 값의 것이다 — 템플릿은 자리가 선다는 것만 말하고 찼는지는 채운 쪽만 안다. | 선택 |
| `value` | 선언된 shape 를 모르는 자리에서 쓰는 느슨한 합집합. 정확한 판정은 검사기가 템플릿을 들고 한다. | 선택 |
| `notes` | 이 값 하나에 대해 할 말. | 선택 |
| `byOption` | 고르는 자리의 고를 것마다 따로 있는 값. 키는 그 자리의 option id 이고 빠짐도 덤도 없이 전부 덮는다. | 선택 |

**`FieldValue`** — 상태는 filled 와 empty 둘뿐이다. 왜 비었는지는 주석이 글로 말한다.

| 자리 | 무엇인가 | 필수·선택 |
| --- | --- | --- |
| `state` | 이 자리가 찼는지. filled 면 value 가 있고 empty 면 없다. | 필수 |
| `value` | 선언된 shape 를 모르는 자리에서 쓰는 느슨한 합집합. 정확한 판정은 검사기가 템플릿을 들고 한다. | 선택 |
| `notes` | 이 값 하나에 대해 할 말. 왜 비었는지도 여기에 글로 적는다. | 선택 |

**`Value`** — 선언된 shape 를 모르는 자리에서 쓰는 느슨한 합집합. 정확한 판정은 검사기가 템플릿을 들고 한다.

**`ValueSingle`** — 타입을 모르는 자리에서 쓰는 느슨한 홑값. 정확한 판정은 선언된 타입으로 한다.

**`ValueRange`** — 구간. 한쪽만 알아도 담는다.

| 자리 | 무엇인가 | 필수·선택 |
| --- | --- | --- |
| `min` | 타입을 모르는 자리에서 쓰는 느슨한 홑값. 정확한 판정은 선언된 타입으로 한다. | 선택 |
| `max` | 타입을 모르는 자리에서 쓰는 느슨한 홑값. 정확한 판정은 선언된 타입으로 한다. | 선택 |

**`ValueSeries` 의 한 칸** — 축 위의 점들. at 은 오름차순이고 겹치지 않는다.

| 자리 | 무엇인가 | 필수·선택 |
| --- | --- | --- |
| `at` | 가로축 위의 자리. 필드가 선언한 axis 의 타입으로 읽는다. | 필수 |
| `value` | 그 자리의 값. 필드가 선언한 type 으로 읽는다. | 필수 |

**`ValueItems`** — 반복 항목. 각 항목은 선언된 열의 부분집합을 채운다. 없는 열은 빈 칸이다.

### 렌더 인자 — [`weave-render-args.schema.json`](../schema/weave-render-args.schema.json)

어느 쪽 문서도 아니다 — 화면 상태다. **볼 때** 정해진다. 사람이 누를 때마다 바뀐다.

**문서 뿌리** — 값이 아니라 화면 상태다. 앱이 갖고 사용자가 누를 때마다 바뀐다. index 가 아니라 subject 의 id 로 가리킨다. 누가 자리에 서는지는 값 한 벌들이 이미 말하므로 여기 없다 — subject 마다 값 한 벌이 정확히 하나 있고, 비어 있을 수 있다. 여기 서는 것은 값에서 유도할 수 없는 것뿐이다: 무엇을 보고 있고 바로 전에 무엇을 보고 있었는지는 앱만 안다.

| 자리 | 무엇인가 | 필수·선택 |
| --- | --- | --- |
| `focus` | 강조할 subject. null 이 release 다. 없는 id 면 focus 만 사라진다. | 선택 |
| `previousFocus` | 바로 전에 보고 있던 subject. 값에서 유도할 수 없는 상호작용 이력이라 여기 선다. focus 와 같은 규칙이다 — null 이 없음이고, 없는 id 면 그 상태만 사라진다. focus 와 같은 id 면 직전이 없는 것으로 본다: 직전이 현재와 같을 수는 없다. | 선택 |
| `choices` | 고르는 자리마다 무엇을 골랐는지. 키는 템플릿 choices 의 id 이고 값은 그 자리의 option id 다. 사람이 누른 것이라 값에서 유도할 수 없다. 무엇을 고를 수 있는지는 템플릿이 이미 말하므로 여기 서지 않는다. 빠진 자리나 없는 id 는 렌더가 **첫 option** 으로 본다 — 늘어놓기로 돌아가지도, 빈 화면을 내지도 않는다. | 선택 |

### weave 공통 정의 — [`weave-common.schema.json`](../schema/weave-common.schema.json)

두 문서가 함께 쓴다. 쓰는 자리를 따른다 — 템플릿에 선 것은 저작 때, 값 한 벌에 선 것은 채울 때.

**문서 뿌리** — 타입·모양·primitive element·주석의 닫힌 어휘. 이 파일이 렌더가 의존하는 전부다.

**`Version`** — 스키마 버전. 지금은 1 뿐이다.

**`Key`** — 템플릿이 짓는 이름. facet id · 필드 key · 열 key 가 쓴다.

**`ExternalId`** — 바깥에서 온 식별자. 템플릿 id 와 subject id 가 쓴다.

**`Number`** — 숫자. 기본 단위 없음.

**`Money`** — 금액. 기본 단위 원, 정수.

**`Ratio`** — 비율. 기본 단위 분수(0.5 = 50%).

**`Multiple`** — 배수. 1 이 「낸 만큼」이고 2 가 「두 배」다. 비율(ratio)과 다르다 — 0.049 가 4.9% 이고 4.9 가 4.9 배다.

**`Duration`** — 기간. 기본 단위 개월, 정수(20년 = 240).

**`Age`** — 나이. 기본 단위 세, 정수.

**`Boolean`** — 참거짓.

**`Text`** — 글. 긴 설명은 값이 아니라 주석에 둔다.

**`Date`** — 날짜. ISO 8601 YYYY-MM-DD.

**`Scalar`** — 타입을 모르는 자리에서 쓰는 느슨한 홑값. 정확한 판정은 선언된 타입으로 한다.

**`Annotation`** — 주석 하나. 갈래와 글뿐이고 확실성 수치는 없다.

| 자리 | 무엇인가 | 필수·선택 |
| --- | --- | --- |
| `kind` | 주석의 갈래. 넷뿐이고 확실성 수치는 없다. | 필수 |
| `text` | 주석의 글. 한 문단까지다 — 더 길어지면 값이 아니라 문서가 된다. | 필수 |

**`Annotations`** — 한 자리에 붙는 주석들. 템플릿 쪽에 서면 저작자의 말이고 값 한 벌 쪽에 서면 그 subject 에 대한 말이다.

닫힌 어휘는 값이 전부 정해져 있다. 각 값이 무엇인지는 이 문서의 앞 절이 말한다.

| 어휘 | 값 | 각 값이 무엇인지 |
| --- | --- | --- |
| `Type` | `number`·`money`·`ratio`·`multiple`·`duration`·`age`·`boolean`·`text`·`date` | [타입](#타입) |
| `NumericType` | `number`·`money`·`ratio`·`multiple`·`duration`·`age` | [타입](#타입) — 크기를 견줄 수 있는 것만 |
| `OrderedType` | `number`·`money`·`ratio`·`multiple`·`duration`·`age`·`date` | [타입](#타입) — 순서를 매길 수 있는 것만 |
| `AxisType` | `age`·`date`·`duration`·`number` | [타입](#타입) — series 의 가로축이 될 수 있는 것만 |
| `Shape` | `single`·`range`·`series`·`items` | [모양](#모양) |
| `Element` | `stat`·`facts`·`bars`·`line`·`rows`·`parts` | [primitive element](#primitive-element) |
| `Compare` | `focus`·`overlay` | 위 `Facet.compare` |
| `AnnotationKind` | `quote`·`tip`·`note`·`caution` | [주석](#주석) |
